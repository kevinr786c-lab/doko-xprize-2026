- [ ] Confirm project start date and pre-existing-resource disclosure.
- [ ] Keep the repository private unless a deliberate licensing decision is made.
- [ ] Share the private repository with `testing@devpost.com` and
      `judging@hacker.fund`.

      dependencies, setup, and testing instructions.
- [ ] Confirm no secret, receipt, patient data, or production export is tracked.
- [ ] Add the final repository URL to Devpost.

## Public project page

## Demo video

- [ ] Maximum 3 minutes.
- [ ] Show the product functioning on its intended device.
- [ ] Use English narration or readable English captions.
- [ ] Use a test doctor and fictitious patient data.
- [ ] Show live production capability, not only slides.
- [ ] Explain the problem, AI role, human controls, traction, and business model.
- [ ] Avoid unlicensed music and unnecessary third-party branding.

## Judge-only business evidence

- [ ] Upload P&L in the required template and USD.
- [ ] Upload bank/payment evidence matching the P&L.
- [ ] Report monthly cash-basis revenue for May, June, July, and August.
- [ ] Separate pre-existing-customer revenue from independent sales.
- [ ] Report all expenses, including software and token costs.
- [ ] Verify user and paying-user counts use one consistent definition.
- [ ] Explain deliberate onboarding limits as a path to repeatability.

## Testimonials

- [ ] Obtain explicit permission from the assistant for a public testimonial.
- [ ] Obtain explicit permission from the doctor for a public impact testimonial.
- [ ] Publish each testimonial at a verifiable URL.
- [ ] Avoid patient examples and confidential clinic information.
- [ ] Describe observed impact without claiming Doko generated all appointments.
