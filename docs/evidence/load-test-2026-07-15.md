# Doko Panel Assistant Read-Only Load Test

Date: July 15, 2026  
Target: Doko production and local Cloud SQL Auth Proxy  
Account: Internal test doctor; identity omitted

## Safety controls

- No appointments were created, edited, confirmed, cancelled, or released.
- No email was sent.
- Google Calendar synchronization was disabled in local tests.
- Gemini calls were disabled in local tests.
- Production tests used only a read-only day-options endpoint.
- No patient names, phone numbers, appointment details, or search terms were
  printed.

## Results

### Local intent parser

- Requests: 200
- Concurrency: 8
- Successful: 200
- Errors: 0
- p50: 0.06 ms
- p95: 0.14 ms

### Local integration through Cloud SQL Auth Proxy

- Database-backed requests: 60
- Concurrency: 8
- Successful: 60
- Errors: 0
- Google calls: 0
- Gemini calls: 0

The local proxy introduced substantial network latency, so those timings are
not presented as Cloud Run production latency.

### Production read-only, medium concurrency

- Requests: 12
- Concurrency: 4
- Successful: 12
- Errors: 0
- p50: 2.23 s
- p95: 2.28 s
- Throughput: 1.74 requests/s

### Production read-only, full configured thread concurrency

- Requests: 16
- Concurrency: 8
- Successful: 16
- Errors: 0
- p50: 3.09 s
- p95: 3.51 s
- Maximum: 3.65 s
- Throughput: 2.37 requests/s

## Conclusion

The local intent interpreter completed all requests without error. The
production read-only path completed every request at the configured eight-thread
instance concurrency without errors. This supports the planned initial cohort;
it is not a claim of unlimited scale.

The next performance target is reducing database round trips so p95 latency can
remain below two seconds as usage grows.
